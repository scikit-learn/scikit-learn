Version 1.10.0
==============

**October 2026**

Changed models
--------------

- :class:`preprocessing.QuantileTransformer` and
  :func:`preprocessing.quantile_transform` now estimate quantiles with the
  `averaged_inverted_cdf` method and no longer cap `n_quantiles` at `n_samples`.
  Dense subsampling is also done with replacement. These changes affect `quantiles_`
  even when `sample_weight` is not passed.
  By :user:`Karassay Raushanbek <kaekkr>` and :user:`Shruti Nath <snath-xoc>`. :pr:`32761`

- :class:`ensemble.HistGradientBoostingClassifier` and
  :class:`ensemble.HistGradientBoostingRegressor` now draw the subset of
  features considered at each split differently when `max_features < 1.0`.
  For a fixed `random_state`, the selected features, and hence the fitted
  trees, may differ from previous versions.
  By :user:`Arthur Lacote <cakedev0>`. :pr:`34786`

- :func:`inspection.partial_dependence` and :class:`inspection.PartialDependenceDisplay`
  now use `numpy.nanquantile`'s linear interpolation instead of the (unmaintained)
  `scipy.stats.mstats.mquantiles`'s Cunnane interpolation to compute the grid of
  values and deciles from `X`. This may slightly shift the computed grid values
  and displayed deciles. `np.nan` values in a numerical column are now ignored
  (instead of being sorted last in the quantile calculation and hence possibly
  affecting the result depending on the requested percentiles).
  By :user:`Arthur Lacote <cakedev0>`. :pr:`34928`

Changes impacting many modules
------------------------------

- |Efficiency| Hot-loop NaN checks in :mod:`sklearn.tree` and
  :mod:`sklearn.ensemble` (histogram gradient boosting) now use a
  scikit-learn-local, always-inlined `isnan` helper instead of
  `libc.math.isnan()`, avoiding a non-inlined libm call on platforms/libc
  versions where the compiler cannot inline it (notably affecting fit
  performance of :class:`ensemble.ExtraTreesRegressor` and
  :class:`ensemble.ExtraTreesClassifier` on some conda-forge builds).
  By :user:`Arthur Lacote <cakedev0>`. :pr:`34876`

---------------------

Additional estimators and functions have been updated to include support for all
`Array API <https://data-apis.org/array-api/latest/>`_ compliant inputs.

See :ref:`array_api` for more details.

  By :user:`Tim Head <betatim>` :pr:`33573`

- |Feature| :class:`covariance.OAS` now supports array API compatible inputs.
  By :user:`Bruno Aristimunha <bruAristimunha>` :pr:`33600`

  with `solver="lbfgs"` and `solver="newton-cg"` and when the underlying scoring
  function is also compatible with the array API.
  By :user:`Omar Salman <OmarManzoor>` and :user:`Christian Lorentzen <lorentzenchr>`. :pr:`33906`

- |Feature| :func:`sklearn.metrics.matthews_corrcoef` now supports array API compatible inputs.
  By :user:`Mohamad Fazeli <Fazel94>`. :pr:`34423`

  compatible inputs.
  By :user:`Yaroslav Korobko <Tialo>` and :user:`Omar Salman <OmarManzoor>`. :pr:`34785`

- |Enhancement| Add support for array inputs from mixed namespaces and devices for:
  :func:`sklearn.metrics.det_curve`,
  :func:`sklearn.metrics.roc_curve`,
  :func:`sklearn.metrics.zero_one_loss`,
  :func:`sklearn.metrics.jaccard_score`,
  :func:`sklearn.metrics.balanced_accuracy_score`,

  By :user:`Lucy Liu <lucyleeow>`. :pr:`34442`

  By :user:`Christian Lorentzen <lorentzenchr>` and :user:`Omar Salman <OmarManzoor>`. :pr:`34412`

- |Fix| Fixes support when `average="samples"` and `sample_weight` is an array from a

  :func:`sklearn.metrics.recall`,
  :func:`sklearn.metrics.precision`,
  :func:`sklearn.metrics.f1_score`,
  :func:`sklearn.metrics.fbeta_score`.
  Also fixes several bugs in array API compliance of
  :func:`sklearn.metrics.roc_curve`.
  By :user:`Lucy Liu <lucyleeow>`. :pr:`34442`

- |Fix| :class:`discriminant_analysis.LinearDiscriminantAnalysis` now supports array

  By :user:`Kiyarash Fazeli <Fazel94>`. :pr:`34475`

- |Fix| :class:`linear_model.PoissonRegressor` now accepts `y` and `sample_weight`

  By :user:`Amineh Dadsetan <aminehd>`. :pr:`34480`

Metadata routing
----------------

Refer to the :ref:`Metadata Routing User Guide <metadata_routing>` for
more details.

- |Feature| |Feature| Added support for auto-requesting metadata through
  ``set_config(enable_metadata_auto_requests=True)``. This enables automatic routing of
  common metadata like ``sample_weight``, or ``X_val``. :term:`Consumers <consumer>`
  (estimators, scorers, and CV splitters) and consuming :term:`routers <router>` can now
  define which metadata requests to set automatically via the ``add_auto_request``
  method, which complements the existing class-level defaults set through
  ``__metadata_request__*`` attributes. Refer to :ref:`metadata_routing_auto_request`
  for more details.
  By `Adrin Jalali`_ and :user:`Stefanie Senger <StefanieSenger>`. :pr:`31413`

- |Feature| |Feature| :class:`~ensemble.HistGradientBoostingClassifier` and
  :class:`~ensemble.HistGradientBoostingRegressor` auto-request `X_val`, `y_val` and
  `sample_weight_val` when metadata routing and auto-requests are enabled via
  :func:`~sklearn.set_config`.
  By :user:`Stefanie Senger <StefanieSenger>`. :pr:`34957`

Callbacks
---------

- |Feature| Callbacks can now receive routed metadata such as ``sample_weight``.
  :class:`callback.FitCallback` requests it per hook with
  ``set_on_fit_task_begin_request`` and ``set_on_fit_task_end_request``.
  :class:`callback.ScoringMonitor` can now score on a validation set via ``scoring_val``
  when metadata routing is enabled. It requests ``X_val`` and ``y_val`` automatically and
  routes metadata to the training and validation scorers. While routing is disabled,
  ``sample_weight`` is still forwarded to hooks that accept it. By :user:`François Paugam
  <FrancoisPgm>`. :pr:`34137`

- |API| Custom callbacks must now subclass :class:`callback.FitCallback` (or
  :class:`callback.AutoPropagatedCallback`) instead of implementing the callback
  protocols. ``on_fit_task_begin`` and ``on_fit_task_end`` no longer take a ``metadata``
  dict; requested metadata is passed as keyword arguments.
  :class:`callback.ScoringMonitor` replaces ``scoring`` with ``scoring_train`` and
  ``scoring_val``, and :class:`callback.ScoringMonitorLog` replaces ``data`` and
  ``data_as_pandas`` with ``train_scores``, ``val_scores``, and the corresponding
  ``*_as_pandas`` attributes. By :user:`François Paugam <FrancoisPgm>`. :pr:`34137`

- |API| In :class:`callback.ScoringMonitor`, the option to provide `scoring=None` to have the
  default scorer of the estimator has been removed.
  By :user:`François Paugam <FrancoisPgm>`. :pr:`34590`

:mod:`sklearn.linear_model`
---------------------------

- |MajorFeature| The generalized linear models (GLM) :class:`linear_model.GammaRegressor`,
  :class:`linear_model.PoissonRegressor` and :class:`linear_model.TweedieRegressor`
  are now able to fit L1 and Elastic-Net penalties with the new parameter `l1_ratio`
  together with the 2 new solvers `"newton-cd"` and `"newton-cd-gram"`.
  These new solvers are also available for :class:`linear_model.LogisticRegression`.
  They are based on the Newton solver infrastructure introduced for `"newton-cholesky"`
  and take advantage of the already available and fast (e.g. via gap safe screening
  rules) coordinate descent solvers of :class:`ElasticNet`.

  - `"newton-cd-gram"` constructs the full Hessian (gram) matrix and then uses
    `ElasticNet(precompute=True)` as the inner solver. It is a good choice for
    `n_samples >> n_features`.
  - `"newton-cd"` avoids constructing the full Hessian matrix, but formulates the
    minimization problem for the inner solver as a penalized least squares problem
    (which amounts to taking the square root of the Hessian; this is even done with
    great care for multiclass/multinomial logistic regression using an analytic LDL
    decomposition of the multinomial covariance matrix per sample) and then uses
    `ElasticNet(precompute=False)` on it. It is a good choice for
    `n_features > n_samples`.

    By :user:`Christian Lorentzen <lorentzenchr>`. :pr:`34561`, :pr:`34377`, :pr:`34523`. :pr:`34681`

- |Efficiency| The `"newton-cholesky"` solver of :class:`linear_model.LogisticRegression`,
  :class:`linear_model.GammaRegressor`, :class:`linear_model.PoissonRegressor` and
  :class:`linear_model.TweedieRegressor` now uses an improved backtracking line search.
  Instead of halving the step size in each line search iteration, it uses cubic or
  quadratic polynomial interpolation to find the next trial step size.
  By :user:`Christian Lorentzen <lorentzenchr>`. :pr:`34157`

- |Efficiency| All solvers of :class:`linear_model.LogisticRegressionCV` are now faster on
  free-threaded Python when using parallelism. The only exceptions are ``"sag"``
  and ``"saga"`` solvers, which will continue to run at the same speed.
  By :user:`Itamar Turner-Trauring <itamarst>`. :pr:`34659`

- |Enhancement| :class:`linear_model.PoissonRegressor`, :class:`linear_model.GammaRegressor` and
  :class:`linear_model.TweedieRegressor` got a new solver: `solver="newton-cg"`.
  This is the same Newton conjugate gradient solver, a.k.a. truncated Newton, that is
  already available with :class:`linear_model.LogisticRegression`.
  By :user:`Christian Lorentzen <lorentzenchr>`. :pr:`33759`

- |Enhancement| :class:`linear_model.ElasticNetCV`, :class:`linear_model.LassoCV` and
  :class:`linear_model.MultiTaskElasticNetCV` as well as :func:`enet_path` and
  :func:`lasso_path` are now faster. The (relative) speed-up is larger for lower
  tolerance (larger values of `tol`) and achieved by avoiding to re-calculate the
  residuals and the column norms of `X` for each penalty `alpha` along the path.
  By :user:`Christian Lorentzen <lorentzenchr>`. :pr:`34572`

- |Enhancement| :class:`linear_model.ElasticNetCV`, :class:`linear_model.LassoCV` and
  :class:`linear_model.MultiTaskElasticNetCV` now avoid prematurely converting `X` to
  F-contiguous array or sparse CSC because the inner cross validation take subsamples
  of `X` which then need the same conversion again, anyway. So this PR can avoid memory
  copies of `X`.
  By :user:`Christian Lorentzen <lorentzenchr>`. :pr:`34613`

- |Fix| The `solver="newton-cg"` for :class:`linear_model.LogisticRegression`,
  :class:`linear_model.PoissonRegressor` and other GLMs is now more robust. Many
  convergence issues have been fixed, e.g. for certain ill-conditioned problems with
  low regularization and nearly collinear features. The fix is about treating small
  or even negative curvature.
  By :user:`Christian Lorentzen <lorentzenchr>`. :pr:`34412`

- |API| The parameters `C` of :class:`linear_model.LogisticRegression` and `Cs` of
  :class:`linear_model.LogisticRegressionCV` are deprecated and will be removed in
  version 1.14. The relationship is

  - for `LogisticRegression`: `alpha = 1/C`
  - for `LogisticRegressionCV`: `alphas = Cs` for integer values, `alphas = 1/Cs` for
    array-likes of float

  They have the following default values:

  - `alpha=1.0` for `LogisticRegression`, meaning it is the same default as `C=1.0`.
  - `alphas=10` for `LogisticRegressionCV`, meaning it is the same default as `Cs=10`.

  This means, the defaults result in the same model as before (up to floating point
  precision).

  With this change the penalty parameter of most linear models is `alpha`, the larger
  its value the stronger the penalty. For L2-penalties, the parametrization is
  similar to :class:`linear_model.Ridge` where the penalty gets weaker the larger the
  training dataset (by a factor of `1/n_samples`).

  For :class:`linear_model.LogisticRegressionCV`, also the attributes `C_` and `Cs_`
  are deprecated. Use the new attributes `alpha_` and `alphas_` instead.
  By :user:`Christian Lorentzen <lorentzenchr>`. :pr:`32042`

Version 1.10.0
==============

**October 2026**

Changed models
--------------

- :class:`preprocessing.QuantileTransformer` and
  :func:`preprocessing.quantile_transform` now estimate quantiles with the
  `averaged_inverted_cdf` method and no longer cap `n_quantiles` at `n_samples`.
  Dense subsampling is also done with replacement. These changes affect `quantiles_`
  even when `sample_weight` is not passed.
  By :user:`Karassay Raushanbek <kaekkr>` and :user:`Shruti Nath <snath-xoc>`. :pr:`32761`

- :class:`ensemble.HistGradientBoostingClassifier` and
  :class:`ensemble.HistGradientBoostingRegressor` now draw the subset of
  features considered at each split differently when `max_features < 1.0`.
  For a fixed `random_state`, the selected features, and hence the fitted
  trees, may differ from previous versions.
  By :user:`Arthur Lacote <cakedev0>`. :pr:`34786`

- :func:`inspection.partial_dependence` and :class:`inspection.PartialDependenceDisplay`
  now use `numpy.nanquantile`'s linear interpolation instead of the (unmaintained)
  `scipy.stats.mstats.mquantiles`'s Cunnane interpolation to compute the grid of
  values and deciles from `X`. This may slightly shift the computed grid values
  and displayed deciles. `np.nan` values in a numerical column are now ignored
  (instead of being sorted last in the quantile calculation and hence possibly
  affecting the result depending on the requested percentiles).
  By :user:`Arthur Lacote <cakedev0>`. :pr:`34928`

Changes impacting many modules
------------------------------

- |Efficiency| Hot-loop NaN checks in :mod:`sklearn.tree` and
  :mod:`sklearn.ensemble` (histogram gradient boosting) now use a
  scikit-learn-local, always-inlined `isnan` helper instead of
  `libc.math.isnan()`, avoiding a non-inlined libm call on platforms/libc
  versions where the compiler cannot inline it (notably affecting fit
  performance of :class:`ensemble.ExtraTreesRegressor` and
  :class:`ensemble.ExtraTreesClassifier` on some conda-forge builds).

:mod:`sklearn.linear_model`
---------------------------

- |MajorFeature| The generalized linear models (GLM) :class:`linear_model.GammaRegressor`,
  :class:`linear_model.PoissonRegressor` and :class:`linear_model.TweedieRegressor`
  are now able to fit L1 and Elastic-Net penalties with the new parameter `l1_ratio`
  together with the 2 new solvers `"newton-cd"` and `"newton-cd-gram"`.
  These new solvers are also available for :class:`linear_model.LogisticRegression`.
  They are based on the Newton solver infrastructure introduced for `"newton-cholesky"`
  and take advantage of the already available and fast (e.g. via gap safe screening
  rules) coordinate descent solvers of :class:`ElasticNet`.

  - `"newton-cd-gram"` constructs the full Hessian (gram) matrix and then uses
    `ElasticNet(precompute=True)` as the inner solver. It is a good choice for
    `n_samples >> n_features`.
  - `"newton-cd"` avoids constructing the full Hessian matrix, but formulates the
    minimization problem for the inner solver as a penalized least squares problem
    (which amounts to taking the square root of the Hessian; this is even done with
    great care for multiclass/multinomial logistic regression using an analytic LDL
    decomposition of the multinomial covariance matrix per sample) and then uses
    `ElasticNet(precompute=False)` on it. It is a good choice for
    `n_features > n_samples`.

    By :user:`Christian Lorentzen <lorentzenchr>`. :pr:`34561`, :pr:`34377`, :pr:`34523`. :pr:`34681`

- |Efficiency| The `"newton-cholesky"` solver of :class:`linear_model.LogisticRegression`,
  :class:`linear_model.GammaRegressor`, :class:`linear_model.PoissonRegressor` and
  :class:`linear_model.TweedieRegressor` now uses an improved backtracking line search.
  Instead of halving the step size in each line search iteration, it uses cubic or
  quadratic polynomial interpolation to find the next trial step size.
  By :user:`Christian Lorentzen <lorentzenchr>`. :pr:`34157`

- |Efficiency| All solvers of :class:`linear_model.LogisticRegressionCV` are now faster on
  free-threaded Python when using parallelism. The only exceptions are ``"sag"``
  and ``"saga"`` solvers, which will continue to run at the same speed.
  By :user:`Itamar Turner-Trauring <itamarst>`. :pr:`34659`

- |Enhancement| :class:`linear_model.PoissonRegressor`, :class:`linear_model.GammaRegressor` and
  :class:`linear_model.TweedieRegressor` got a new solver: `solver="newton-cg"`.
  This is the same Newton conjugate gradient solver, a.k.a. truncated Newton, that is
  already available with :class:`linear_model.LogisticRegression`.
  By :user:`Christian Lorentzen <lorentzenchr>`. :pr:`33759`

- |Enhancement| :class:`linear_model.ElasticNetCV`, :class:`linear_model.LassoCV` and
  :class:`linear_model.MultiTaskElasticNetCV` as well as :func:`enet_path` and
  :func:`lasso_path` are now faster. The (relative) speed-up is larger for lower
  tolerance (larger values of `tol`) and achieved by avoiding to re-calculate the
  residuals and the column norms of `X` for each penalty `alpha` along the path.
  By :user:`Christian Lorentzen <lorentzenchr>`. :pr:`34572`

- |Enhancement| :class:`linear_model.ElasticNetCV`, :class:`linear_model.LassoCV` and
  :class:`linear_model.MultiTaskElasticNetCV` now avoid prematurely converting `X` to
  F-contiguous array or sparse CSC because the inner cross validation take subsamples
  of `X` which then need the same conversion again, anyway. So this PR can avoid memory
  copies of `X`.
  By :user:`Christian Lorentzen <lorentzenchr>`. :pr:`34613`

- |Fix| The `solver="newton-cg"` for :class:`linear_model.LogisticRegression`,
  :class:`linear_model.PoissonRegressor` and other GLMs is now more robust. Many
  convergence issues have been fixed, e.g. for certain ill-conditioned problems with
  low regularization and nearly collinear features. The fix is about treating small
  or even negative curvature.
  By :user:`Christian Lorentzen <lorentzenchr>`. :pr:`34412`

- |API| The parameters `C` of :class:`linear_model.LogisticRegression` and `Cs` of
  :class:`linear_model.LogisticRegressionCV` are deprecated and will be removed in
  version 1.14. The relationship is

  - for `LogisticRegression`: `alpha = 1/C`
  - for `LogisticRegressionCV`: `alphas = Cs` for integer values, `alphas = 1/Cs` for
    array-likes of float

  They have the following default values:

  - `alpha=1.0` for `LogisticRegression`, meaning it is the same default as `C=1.0`.
  - `alphas=10` for `LogisticRegressionCV`, meaning it is the same default as `Cs=10`.

  This means, the defaults result in the same model as before (up to floating point
  precision).

  With this change the penalty parameter of most linear models is `alpha`, the larger
  its value the stronger the penalty. For L2-penalties, the parametrization is
  similar to :class:`linear_model.Ridge` where the penalty gets weaker the larger the
  training dataset (by a factor of `1/n_samples`).

  For :class:`linear_model.LogisticRegressionCV`, also the attributes `C_` and `Cs_`
  are deprecated. Use the new attributes `alpha_` and `alphas_` instead.
  By :user:`Christian Lorentzen <lorentzenchr>`. :pr:`32042`

- |Efficiency| :class:`mixture.GaussianMixture` with ``covariance_type="tied"`` is now faster,

  By :user:`Roman Yurchak <rth>`. :pr:`1140`

:mod:`sklearn.model_selection`

  By :user:`Pranav Negi <825pranav>`. :pr:`35042`

:mod:`sklearn.neighbors`
------------------------

- |Feature| :class:`neighbors.NeighborhoodComponentsAnalysis` now supports sparse
  input matrices for ``init`` in ``['pca', 'random', 'identity']``. By
  :user:`Arturo Amor <ArturoAmorQ>`. :pr:`34122`

- |Efficiency| :meth:`neighbors.KNeighborsRegressor.predict` is now faster for regression with
  many output targets.
  By :user:`Roman Yurchak <rth>`. :pr:`1140`

* |Efficiency| :class:`sklearn.neighbors.KNeighborsClassifier` is now faster when running with multiple threads. The statistics returned from :class:`sklearn.neighbors.BallTree` and :class:`sklearn.neighbors.KDTree` no longer reset on each query, and are no longer incorrect when the tree is used from multiple threads.
  By :user:`Itamar Turner-Trauring <itamarst>`. :pr:`34187`

* |Efficiency| :class:`sklearn.neighbors.KNeighborsClassifier` is now faster when fitting when used with :class:`sklearn.neighbors.BallTree` or :class:`sklearn.neighbors.KDTree`.
  By :user:`Itamar Turner-Trauring <itamarst>`. :pr:`34564`

* |Efficiency| :class:`sklearn.neighbors.KDTree` is now faster for most distance metrics, so for example :class:`sklearn.neighbors.KNeighborsClassifier` has faster fitting and prediction when using kdtrees.
  By :user:`Itamar Turner-Trauring <itamarst>`. :pr:`35045`

- |API| Getting statistics and number of calls from :class:`sklearn.neighbors.BallTree` and
  :class:`sklearn.neighbors.KDTree` is deprecated. The relevant APIs will be removed in

:mod:`sklearn.pipeline`
-----------------------

- |Fix| The default value for the `transform_input` parameter of :class:`Pipeline` was changed
  from `None` to `("X_val",)` so that the validation set, when passed to `fit`, is
  always transformed alongside `X`, to prevent easy to miss mistakes.
  By :user:`Jérémie du Boisberranger <jeremiedbb>`. :pr:`34263`

:mod:`sklearn.preprocessing`
----------------------------

- |Efficiency| Improved fit time of :class:`preprocessing.OneHotEncoder`
  and :class:`preprocessing.OrdinalEncoder` on object/string categorical
  features when category counts are needed, for instance with ``min_frequency``
  or ``max_categories``.
  By :user:`Itamar Turner-Trauring <itamarst>`. :pr:`34386`

- |Efficiency| :class:`preprocessing.OneHotEncoder`, :class:`preprocessing.OrdinalEncoder`,
  and :class:`preprocessing.TargetEncoder` are now faster by using a
  Fortran-contiguous memory layout in their encoding paths.
  By :user:`Arthur Lacote <cakedev0>`. :pr:`34392`

- |Enhancement| :class:`preprocessing.QuantileTransformer` can now handle sample weight values
  by subsampling using sample weights if subsampling is enabled or otherwise using
  `_weighted_percentile`. The default method of calculating percentiles for both
  weighted and unweighted cases is now fixed to "averaged_inverted_cdf".
  Support is only implemented for dense X.
  By :user:`Karassay Raushanbek <kaekkr>` and :user:`Shruti Nath <snath-xoc>`. :pr:`32761`

- |Fix| A few edge cases with missing values and unique knot values in
  :class:`preprocessing.SplineTransformer` are now handled correctly.
  For instance, if a feature is constant, i.e., has only one unique value at fit time,
  `transform` now always returns all zeros for that feature.
  By :user:`Christian Lorentzen <lorentzenchr>`. :pr:`33953`

- |Fix| The warning raised by :class:`preprocessing.OneHotEncoder` now distinguishes
  columns where unknown categories are encoded as the infrequent category from
  columns where they are encoded as all zeros.
  By :user:`oathbreaker <karansgotit>`. :pr:`34861`

:mod:`sklearn.tree`
-------------------

- |MajorFeature| :class:`tree.DecisionTreeRegressor`, :class:`tree.DecisionTreeClassifier`
  now have native support for categorical features for binary classification and
  single-output regression. All criteria are supported except for `'absolute_error'`.
  Categorical features can be specified with the `categorical_features` parameter.
  Up to 256 categories per features are supported.
  By :user:`Adam Li <adam2392>`, :user:`Arthur Lacote <cakedev0>`,
  :user:`Adrin Jalali <adrinjalali>` and :user:`Christian Lorentzen <lorentzenchr>` :pr:`33354`

- |MajorFeature| :class:`tree.DecisionTreeRegressor`, :class:`tree.DecisionTreeClassifier`,
  :class:`tree.ExtraTreeRegressor`, and :class:`tree.ExtraTreeClassifier`
  now have native support for categorical features via the `categorical_features`
  parameter. Decision trees support binary classification and single-output
  regression (all criteria except `'absolute_error'`) with up to 256 categories
  per feature. Extra trees also support multi-class / multi-output targets with
  up to ``2**24 - 1`` categories via random hash splits.
  By :user:`Adam Li <adam2392>`, :user:`Arthur Lacote <cakedev0>`,
  :user:`Adrin Jalali <adrinjalali>` and :user:`Christian Lorentzen <lorentzenchr>` :pr:`33972`

- |Feature| Added a ``fill_colors`` parameter to :func:`tree.plot_tree` and
  :func:`tree.export_graphviz` to allow user-defined class colors when
  rendering filled decision trees.
  By :user:`Simon-Martin Schröder <moi90>`. :pr:`33810`
